Free feature checklist from competitor research

Features that competitors give away in their free versions. MemberGlut Free should match most of these to compete on wordpress.org.

Researched from the readme and source code of: Members, Paid Member Subscriptions, Restrict User Access, s2Member, Simple Membership, SureMembers, Ultimate Member, User Registration & Membership, ProfilePress, WP-Members, WP User Frontend, Membership for WooCommerce and WCFM Membership (installed versions, Oct 2026).

P1 = must have for launch, P2 = important, P3 = nice to have. In MemberGlut = a version already exists in the current code (check how complete it is). Tick Done as you implement; progress is saved in this browser.

Membership Plans & Levels 13

The core object of the plugin. Every competitor has a plan (level, access group or subscription plan) that ties together price, duration, a role and the content it unlocks.

Unlimited membership plans / levels

P1In MemberGlut

Create as many plans as needed (Free, Silver, Gold…). Each plan stores: name, slug, description, status (active/inactive), price, duration and the WP role to assign. Use a custom table (memberglut_plans) or a CPT. Inactive plans stay attached to existing members but are hidden from signup forms (PMS has an option to still show them in the restriction metabox).

PMSSWPMSMRUAURMPPS2MFWWCFMWPUF

Free and paid plans side by side

P1Partial in MG

A price of 0 means a free plan. It skips the gateway and activates right away, optionally after email confirmation or admin approval. Paid plans go through checkout. Both types appear in the same plan selector on the registration form.

PMSSWPMURMPPWCFMS2

Flexible duration models

P1Partial in MG

Supported durations: unlimited/lifetime, fixed length (X days/weeks/months/years), a fixed future expiry date, and annual calendar or fiscal-year memberships (SWPM). Store duration + duration_unit per plan and compute expires_at per member subscription. A daily cron expires overdue subscriptions.

SWPMPMSPPURMMFW

Plan hierarchy / tiers (upgrade & downgrade paths)

P1Partial in MG

Plans belong to a tier group with an order (Free < Silver < Gold). Members can upgrade or downgrade inside the group from their account page. PMS has the options "Allow Subscription Downgrades" and "Allow Subscription Change" (to another tier), plus "Apply sign-up fees to upgrades/downgrades". URM has membership groups with drag-to-reorder upgrade paths, and the upgrade type can be full amount or proration.

PMSURMUMMEM

Membership groups (grouped plan listing)

P2

Groups bundle related plans for the front-end pricing listing and upgrade paths, e.g. a 'Courses' group and a 'Community' group. They are rendered by a shortcode/block that shows the plans in a group as a pricing table.

URMPP

Free trial period

P1

Per-plan trial length (days/weeks/months). For recurring gateways, pass the trial to Stripe/PayPal. For manual plans, start the subscription in a 'trialing' status and charge when the trial ends. Prevent repeat trials by flagging users who already used one. PP sends a 'trial ending' reminder email.

PMSURMPPWCFMMFW

Sign-up / setup fee

P2

A one-time fee added to the first payment, separate from the recurring amount. PMS can optionally charge it again on upgrades and downgrades.

PMSPPMFW

Pay in installments (limited billing cycles)

P2

A recurring plan that stops after N payments. PMS calls these 'Limit Payment Cycles' / 'Number of Payments', with a 'Status After Last Cycle' choice: keep active forever or expire. Track processed_billing_cycles on the subscription.

PMSWCFM

Duplicate plan

P3

Clone a plan with all its settings and content rules, then edit the copy. A simple row action in the plans list.

SMPP

Plan-based role assignment

P1In MemberGlut

Each plan maps to a WP role (or adds a secondary role). On activation, add the role. On expiry or cancellation, remove it and fall back to the default role. If a user has several plans, keep the highest-priority role.

PMSUMSMURMSWPMWCFM

Auto-assign plan on registration / default level

P1Partial in MG

Setting: 'New User Default Level/Plan' is granted when any WP user registers, including registrations from other plugins. RUA also has 'New User Default Role'.

SMRUAURM

Member count & plan stats

P2In MemberGlut

Show active, expired and pending member counts per plan in the list table. PMS has a [pms-count-members] shortcode for front-end social proof.

PMSSMMEM

Limit purchase per plan / members-only plans

P3

Restrict who can buy a plan, e.g. only existing members can buy an upgrade-only plan, or a plan is hidden from the pricing table (WCFM 'Hide from Plan Table'). A 'Featured' flag highlights a plan in the table (WCFM).

MFWPMS

Roles & Capabilities 12

A role editor is a strong free differentiator (the Members plugin's whole product). MemberGlut already focuses on this.

Role editor: create / edit / delete roles

P1In MemberGlut

A UI for all WP roles with capability checkboxes grouped by type (posts, pages, media, users, plugin caps). Built-in roles are protected (no deleting administrator or the default role). Show a count of users per role.

MEMUMSM

Clone role

P2Partial in MG

Build a new role starting from an existing role's capabilities.

MEM

Explicitly deny capabilities

P1

A capability has three states: grant, deny or not set. Deny wins over grants from other roles, which is useful with multiple roles per user. Apply it in the user_has_cap filter. RUA applies level capabilities that override roles.

MEMRUA

Multiple roles per user

P1

Replace the single-role dropdown on the user edit and new-user screens with checkboxes. Keep the primary role first in wp_capabilities.

MEM

Custom capabilities

P1In MemberGlut

Admins can add arbitrary capabilities. s2Member uses 'custom capabilities' (access_s2member_ccap_X) as sellable packages of access that sit on top of levels.

MEMS2

Capability groups / tabs by post type & plugin

P2In MemberGlut

Group capabilities by post type, taxonomy and integrated plugin (WooCommerce, EDD, ACF, GiveWP, Meta Box). Others can register their groups through a registry API (members_register_cap_group).

MEM

Extra fine-grained core caps

P3

Members add-ons add create_posts/create_pages (separate from edit), category/tag management caps, privacy/GDPR caps, and role levels for the author dropdown bug.

MEM

Role hierarchy / priority

P2Partial in MG

Roles get a numeric level. Users can only edit or promote users with lower roles. UM's 'Role Priority' decides which role's settings apply when a user has several roles.

MEMUM

Per-role behaviour settings

P1

Ultimate Member stores per role: can access wp-admin, force-hide the admin bar, can edit or delete own profile, can view other profiles (which roles), can make the profile private, registration status (auto-approve / email activation / admin review), and actions after login, logout, registration and account deletion (redirect to profile, URL or wp-admin, refresh).

UM

Role import / export with preview

P2In MemberGlut

Export all or selected roles plus settings to JSON. On import, preview each role and choose import, skip, overwrite or rename. Protected roles cannot be overwritten.

MemberGlut has import/export in Pro. Members gives it away free, so consider moving at least export to free.

MEM

Administrator rescue (magic link)

P2

If an admin locks themselves out while editing roles, wp-login.php?action=…_rescue emails a 15-minute one-time link that restores the administrator role and plugin caps. Rate-limited per IP. Only real administrators or super admins are eligible.

MEM

Capability change log

P3In MemberGlut

An audit log of who changed which capability on which role, and when.

Content Restriction 25

Ways to lock content. This is the most heavily competed area: almost everything below is free in at least one big competitor.

Per post / page / CPT restriction metabox

P1In MemberGlut

A sidebar metabox on every public post type: who can access it (everyone / logged in / logged out / selected plans / selected roles). Inline overrides: custom message, custom redirect URL, a different message for logged-in non-members and for logged-out users (PMS).

PMSUMSWPMSMPPWPMURMS2MEM

Restrict whole site (private site)

P1In MemberGlut

Make the entire front end and RSS feed members-only, with exceptions for the login, registration and password pages and an allow-list of pages. Members also has 'private feed' and 'REST API requires login'.

MEMURMSMPP

Rule-based global restriction (access rules engine)

P1Partial in MG

A separate 'Access Rules' list. A rule = content to protect + exclusions + who can access + action. Content targets: all of a post type, specific posts, child of X, taxonomy terms, archives, author, page template, front page, blog page, search page, 404 page, the whole site. RUA allows AND-combinations (e.g. posts tagged Premium AND by author X). SureMembers adds rule priority when several rules match.

SMPPURMRUA

Taxonomy / category-level restriction

P1

Restrict every post in a category or tag, and the term archive itself. PMS adds a restriction box on the term edit screen. s2Member has category- and tag-level access restrictions by member level.

PMSS2RUAPPSM

URL / URI restriction (with wildcards / regex)

P1

Protect anything that isn't a post, such as custom routes or BuddyPress pages, by URL pattern. SureMembers supports regular expressions in free. s2Member has 'URI Level Access Restrictions'. RUA sells this as a premium add-on.

SMS2

Partial content restriction shortcode

P1Partial in MG

Wraps part of a post, e.g. [restrict plans="1,2" roles="editor" logged_in="1" not="gold"]...[/restrict]. Support negation (RUA level="!platinum"), showing a fallback page's content to others (RUA page="1"), and s2Member's nested [s2If] conditionals with PHP-like conditions.

PMSUMSWPMSMPPWPMURMRUAMEMS2

Gutenberg block restriction

P1

Every block gets a 'Visibility / Permissions' inspector panel: show/hide by logged-in status, role, capability or plan. Also add a 'Content Restriction' wrapper block (URM, PMS start/end blocks). Members does this for free; SureMembers sells it as premium.

MEMPMSPPURM

Page builder restriction (Elementor, Divi, Beaver, Bricks)

P2

Restrict Elementor sections and widgets, Divi modules/sections and Beaver Builder modules by plan or login status from each builder's own UI. PMS also integrates with Kadence, SiteOrigin and WPBakery.

PMSPP

Teaser / excerpt for restricted content

P1In MemberGlut

Instead of hiding everything, show an excerpt (N words, WPM 'Auto Excerpt' with a custom 'read more'), excerpt + message, or excerpt + global message. PP adds a 'blur & fade' style over the teaser.

SWPMPMSPPWPMRUASMUM

Restriction message templates (global + per rule)

P1In MemberGlut

A global rich-text message for non-members, a different one for logged-out visitors and logged-in non-members, and per-post overrides. Smart tags like {{sign_up}} and {{log_in}} render buttons (URM).

PMSUMPPSWPMURM

Unauthorized action: message / redirect / login page / template

P1In MemberGlut

What happens on denial: show a message in place of the content, redirect to a URL or to the login page with a return URL, show a login or registration form inline (URM 'Show UR Form'), render a shortcode, or load a different page template for restricted posts (PMS, PP 'Restricted Page Template').

PMSUMPPSMURMRUA

Hide restricted content from queries / archives / search

P1In MemberGlut

Option to exclude restricted posts from the main query, archives, search results and widgets, or to show them with an excerpt only. UM: 'Hide from queries'. PMS: 'Include Restricted Posts in Queries'. RUA: 'How to display content in lists'.

PMSUMSMRUAURM

REST API content protection

P1In MemberGlut

Restricted posts must not leak through /wp-json/wp/v2/posts. Filter rest_prepare_{post_type} and the query args. RUA also limits REST endpoints to least privilege.

RUASMURM

Restrict comments

P2In MemberGlut

Hide or close comments on restricted posts, and an option to let only members comment anywhere.

PMSSWPM

Feed (RSS) protection

P2In MemberGlut

Replace restricted content in feeds with an excerpt or message. Members can make the whole feed private. s2Member 'Alternative View Protection' covers feeds and search.

MEMS2

Navigation menu item visibility

P1In MemberGlut

Per menu item: everyone / logged in / logged out / specific roles / specific plans. A custom walker field in Appearance → Menus, plus block navigation support. PMS sells plan-based menu filtering as an add-on, but UM, PP and SM give it free.

UMPPSMRUAWPMPMS

Widget / sidebar visibility

P3In MemberGlut

Hide widgets or entire widget areas by role or plan.

RUAMEM

Protect attachments / galleries

P2

Protect attachment pages and gallery images. Real file protection (direct URL) is a Pro feature; see pro_features.html.

SWPM

Login-status access (logged in / logged out)

P1In MemberGlut

The simplest rule: content only for logged-in users, or only for guests (e.g. a 'join now' landing page).

UMPMSPPRUAURM

Restrict by specific users

P3

ProfilePress lets a rule allow a list of specific usernames, alongside roles and plans.

PP

Restriction by user attributes (registration date, email domain, capability, post count…)

P3

URM free conditions include: membership, login status, role, user registered date (before/after/range), registration period, email domain, minimum public posts, capability, registration source and a form field value.

URM

Front-end admin bar 'restrict this page' + editor status

P3

SureMembers adds an admin-bar menu to protect the current page in one click, and shows the restriction status inside the block editor.

SM

Language-based / multilingual conditions

P3

Restrict by language with WPML, Polylang, TranslatePress or Weglot. Also make plan names translatable (wpml-config.xml).

RUA

Restrict BuddyPress / bbPress areas

P3

Restrict forums, topics and BuddyPress profile sections by level. MFW can restrict the BuddyPress dashboard to members.

RUAS2MFW

Lockout-safe defaults

P1

Administrators always bypass restrictions. Deactivating the plugin unlocks all content, and roles are never permanently altered.

Payments & Checkout 18

Free competitors ship at least PayPal + Stripe (one-time and recurring) and bank transfer.

Stripe (one-time + recurring, SCA, Payment Element)

P1

Stripe Connect onboarding (PMS/PP) or API keys with test/live modes. Use the Payment Element so Apple Pay, Google Pay, Link, iDEAL, Bancontact, SEPA, Klarna and others work without extra code. Support 3D Secure/SCA, saved cards, and webhooks for renewals, failures, refunds and cancellations.

PP's free Stripe adds a 2% application fee that Pro removes. That is one way to monetize free payments.

PMSSWPMURMPPWCFM

PayPal (Standard / Checkout API, one-time + recurring)

P1

PayPal Commerce Platform / Checkout (PPCP) with Smart Buttons and subscriptions, plus legacy PayPal Standard with IPN. s2Member also does PDT auto-return and EOT handling. Handle IPN/webhook verification.

PMSSWPMURMS2WCFMPP

Bank transfer / manual / offline payment

P1

Checkout creates a pending payment and emails bank details. The admin marks it paid, which activates the subscription. PMS: 'Redirect after a manual payment' and a 'pending manual payment' email.

PMSURMPPWCFM

Braintree one-time payments

P3

Simple Membership supports Braintree buttons for one-time payments.

SWPM

Payment buttons (shortcode buttons per plan)

P2

Instead of a full checkout, create 'buy buttons' per plan and gateway, then drop a shortcode such as [swpm_payment_button id=..] or [s2Member-PayPal-Button] anywhere.

SWPMS2

On-site checkout page / registration + payment in one step

P1

One form for account fields, plan choice, billing fields and payment method. AJAX checkout with an order summary (PMS 'Order Summary'). Logged-in users skip the account fields. Optional billing address fields (PP checkout field manager).

PMSPPURM

Discount / coupon codes

P1

Percent or fixed amount. Options: specific plans, start and expiry dates, max total uses, max uses per user, new users only, applies to the first payment or to all recurring payments, and CSV bulk upload (PMS). MFW sends a one-time coupon to new members.

URM sells coupons in Pro, but PMS and PP give them free.

PMSPP

Currency settings & formatting

P1

Currency, symbol position, thousand/decimal separators, number of decimals and price display format.

PMSWPUFPP

Test / sandbox mode

P1

A global test mode toggle that uses gateway sandbox keys, with a visible admin notice while it is on.

PMSSWPMWCFMWPUF

Payment history & transactions

P1

An admin list of all payments (amount, gateway, status, transaction ID, plan, user) with filters, search, add/edit manual payment, and a payment log per payment. Members see their own history ([pms-payment-history]).

PMSSWPMURMPPWPUF

Refunds from the dashboard

P2

Refund through the gateway API from the payment screen, with a setting for whether a refund cancels access.

PMS

Failed payment retry (dunning)

P1

Retry failed renewals: max retries, retry interval, and the subscription status during retries. Send a 'payment failed' email with a link to update the card.

PMSWPUF

Renewals via Action Scheduler

P2

Process scheduled renewals and expirations with Action Scheduler (hourly) instead of a daily wp-cron, which scales better. Admin view of scheduled payments and next run.

PMSUM

Payment notification forwarding (IPN relay)

P3

Forward gateway notifications to external URLs. s2Member has API notification URLs for signup, registration, payment, modification, cancellation, EOT/deletion and refund/reversal.

SWPMS2

Customers & orders screens

P2

ProfilePress keeps separate Orders, Subscriptions and Customers screens with customer lifetime value and order history, like an e-commerce backend.

PP

Sell digital products / downloads

P3

ProfilePress plans can include downloadable files with download limits and download logs. This is useful for selling e-books alongside memberships.

PP

Tax / EU VAT

P2

Tax rates by country and state, EU VAT with VIES validation and reverse charge. ProfilePress ships eu-vat-rates.json.

Free in ProfilePress, but Pro in PMS, URM and WPUF. Decide which tier this belongs in.

PP

Pay-per-post / posting packs

P3

WPUF sells subscription packs that limit how many posts of each post type a member can submit, with post expiration and a fallback pay-per-post charge.

Subscription Lifecycle 7

What happens to a membership after purchase. These states and actions drive emails, roles and access.

Subscription statuses

P1Partial in MG

At least: pending, active, trialing, canceled (access until period end), expired, abandoned, on-hold/retrying. Each transition fires an action hook, e.g. memberglut_subscription_status_changed.

PMSURMPPSWPM

Member self-service: renew, cancel, abandon, change plan

P1

From the account page: Renew (before expiry, with a 'show renew button X days before' setting), Cancel (stop auto-renew), Abandon (delete subscription), Upgrade/Downgrade. Each action can be disabled globally (PMS has a toggle per action).

PMSMFWSWPMWCFM

Automatic expiration & demotion

P1Partial in MG

A cron (SureMembers 'expiration sweep') expires overdue subscriptions on time, removes the role and fires hooks. s2Member's EOT (end of term) can demote to a lower level or delete the account.

S2SMSWPMPMS

Admin: grant / revoke / edit expiry manually

P1In MemberGlut

From the members list or the WP user profile: add a plan, change the start or expiry date, or cancel. SureMembers also logs every grant and revoke event (access log).

SMPMSSWPMUMRUA

Multiple active plans per user

P2

RUA and SM let users hold several levels at once, and URM has an 'Allow multiple memberships' setting. PMS sells this as a Pro add-on (one plan per group).

RUASMURM

Prevent repeat trial / duplicate purchase

P2

Block buying the same active plan twice, and block a second free trial.

PMSPP

Membership expiry display

P2

A shortcode for the expiry date ([swpm_show_expiry_date]) and an option to always show the expiration date. Uses the WP date format.
